## Shared S1 Mechanism and Notebook Boundary

**Review-driven design recommendation.** Locmetry decodes the notebook container once and uses Tokei's public cell-text parsers for recognized code languages. The decoder supplies disjoint contributions for S1a and an explicit success/failure result for S1b. Do not first subtract overlapping totals from Tokei's Jupyter output and then replace that implementation: `parse_jupyter` is private, the public path discards failure with `unwrap_or_default()`, and parent accumulation also merges nested blobs. Retaining Tokei means retaining its cell-language counters. S1a/S1b may share one implementation checkpoint if splitting it would temporarily misrepresent failures or duplicate decoding.

**Pinned validity basis.** Use the [nbformat v4.5 schema in nbformat v5.10.4](https://github.com/jupyter/nbformat/blob/v5.10.4/nbformat/v4/nbformat.v4.5.schema.json) for fixture validity. It permits absent kernel/language metadata, string or string-array cell sources, and raw cells. A valid minimal empty fixture is `{"nbformat":4,"nbformat_minor":5,"metadata":{},"cells":[]}`; the review's abbreviated object without the two version fields is not schema-valid. Tokei's rejection is not evidence of invalid nbformat. Define the supported v4 minor versions and decoding requirements before production code; this counter need not become a full notebook-schema validator.

**Recommended counting policy.** Preserve `Jupyter Notebooks` host participation even with zero host code. Treat nonblank Markdown and raw-cell text as host comments and retain blanks; Markdown fences and their content must not also become source contributions. Count recognized code-cell text through Tokei with existing backend settings, joining array fragments without inserting characters. Resolve language-selection precedence, absent-language fallback and unsupported-language signaling explicitly before code; distinguish valid-but-unsupported content from malformed input. Empty notebooks need no code-language inference. A zero-byte file is not a notebook and must fail decoding.

**Evidence boundary.** [Tokei's container parser](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/language/language_type.rs#L216) and [CodeStats accumulation](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/stats.rs#L58) establish the shared mechanism. The existing synthetic-payload test assumes disjoint statistics; it does not prove notebook correctness. The [private guard](../../tests/private_regression.rs) replays frozen statistics through `file_records` and bypasses `scan()`, so retain it for regression protection, not as the S1 oracle. Notebook acceptance must use real synthetic `.ipynb` files through scanning and the CLI. Line equality below applies to the specified cell-text fixtures; it is not a new universal promise about every Tokei language's physical lines. The review's Lingua Franca observation remains outside S1 and unverified here.

## S1a — Correct Notebook Normalization

**Rationale.** A valid notebook containing one Python line reports two; a separate two-line notebook reports four. Markdown-only and fenced-Markdown notebooks are doubled too. Tokei includes every cell's counts in its language blob and in parent statistics, and also merges nested blobs into the parent. Locmetry treats these as disjoint. This violates the existing count-once guarantee, and subtracting blob subtrees from parent counts is unsound. Arithmetic reconciliation cannot detect duplication repeated consistently through files and aggregates, so independent expected-count fixtures are essential.

**Provenance.** [Fresh-build reproduction](../research/tool-lessons-and-gaps.md#notebooks-break-two-existing-measurement-guarantees), [Locmetry backend](../../src/backend.rs), and [Tokei notebook aggregation](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/language/language_type.rs#L279).

- [x] Add public synthetic tests that fail on the one-line and two-line fixtures before changing code.
- [x] Define supported notebook shapes and language resolution using the shared S1 boundary. Add real-file fixtures for missing `kernelspec`, missing `language_info`, string/array source, raw cells beside code, and valid minimal empty notebooks. Valid-but-unsupported language cases must not be called malformed input.
- [x] Establish independent expected contributions for multiple cells, Markdown-only and fenced-Markdown notebooks; include comments, blanks and total lines. Keep outputs and container serialization outside extracted cell counts.
- [x] Decode once at the backend boundary and construct disjoint cell contributions, preserving physical-file identity, zero-code host participation, language contributions, host kind/purpose and additive breakdown semantics.
- [x] Verify recognized and explicitly mapped notebook paths use the same normalization where mapping is supported.
- [x] Guard ordinary source and other embedded-language cases against regressions; retain independent count oracles as well as aggregate equations.

**Completion check.** Real-file end-to-end checks cover the following independent oracles, as well as file/language/folder/workspace accounting. A Markdown fixture containing `first\n\nlast\n` must report zero code, two comments, one blank and three lines. A four-line fenced fixture (heading, opening Python fence, `print(1)`, closing fence) must report zero code, four comments, zero blanks and four lines, with no extra Python source contribution. One/two Python lines remain exactly one/two code lines; a raw text line beside one Python line yields one comment plus one code line. Equivalent string/array sources agree. The valid minimal empty notebook is a successfully decoded zero. Relevant tests fail before the change and pass after it; required checks and the private regression pass, or an unavailable private environment is recorded as outstanding evidence. The private replay alone cannot satisfy this stage.

**Documentation in this stage.** Update [measurement semantics](../measurement.md#counting), the [product measurement model](../PRODUCT.md#measurement-model) where needed, and any affected README example. Describe extracted notebook-cell counts versus serialized JSON lines. Record the backend correction and its tested limits; do not claim complete notebook correctness from two fixtures.

**Review checkpoint.** Confirm that a single container decoder supports S1a and S1b and that nested Markdown cannot be counted twice. Tokei's notebook API limitation is already established; keep Tokei for cell content and avoid a throwaway normalization patch against its Jupyter totals.

## S1b — Expose Unavailable Parsing

**Rationale.** Malformed JSON, wrong notebook structure, and valid notebooks outside Tokei's narrower private model all produce zero-count records, exit 0 and `backend_inaccurate = false`. I/O coverage cannot see that loss. Fixing observability must not turn supported valid notebooks into errors merely because Tokei rejects them. Subtracting unavailable counts as zero later would invent a change. File access, container decoding and supported content counting are separate facts.

**Provenance.** [Reproduced coverage failure](../research/tool-lessons-and-gaps.md#notebooks-break-two-existing-measurement-guarantees), [Tokei fallback](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/language/language_type.rs#L67), and pygount's [explicit processing states](https://github.com/roskakori/pygount/blob/v3.2.0/pygount/analysis.py#L74).

- [x] Add failing tests for malformed JSON, wrong-shaped JSON and zero-byte input, alongside the schema-valid minimal empty notebook and valid shapes covered by S1a.
- [x] Resolve the public failure field name/record shape before serialization changes. Recommendation: always emit a distinct failure collection in new full reports and headlines, including an empty collection when no failures occurred. Make the field optional in the version-1 schema for historical inputs; absence means not recorded, not none. Preserve availability per workspace member as well as merged coverage.
- [x] Set `backend_inaccurate = true` and exit 2 for observed decode/counting failures; distinguish malformed input from valid-but-unsupported content and avoid mislabeling either as an I/O read failure. Update the current unread-only diagnostic branch and member aggregation accordingly.
- [x] Make failure observable through the shared S1 decoder and propagate it through single-root/workspace coverage and all output formats. Keep failure paths in the headline, matching the visibility of unread paths for CI consumers.
- [x] Keep unavailable measurement separate from classification and heuristic findings: a generated file can still be counted production source.
- [x] Update the current handwritten report schema in S1b; S3 is later. Keep absence distinguishable from an empty collection through future typed deserialization. Document that old strict schemas may reject the new field even when newer readers accept old reports; decide compatibility explicitly before landing.
- [x] Amend comparison coverage rules: eligible historical reports lacking failure evidence remain consumable with a coverage finding; absence alone is not an observed failure or proof of completeness. Observed failures or recorded inaccuracy produce exit 2. Avoid a generic processing-state framework beyond the required contract.

**Completion check.** Invalid/zero-byte fixtures are not certified as measured zero, supported valid shapes succeed, and valid empty input remains known zero. Test three report states distinctly: historical missing failure evidence, a new empty failure collection, and observed failures. JSON, terminal and Markdown communicate the same limitation, workspace aggregation retains availability and failures, diagnostics preserve machine-readable stdout, and `backend_inaccurate`/exit 2 are tested. Required checks and private regression follow the same evidence rule as S1a.

**Documentation in this stage.** Update [coverage guarantees](../PRODUCT.md#reporting-and-coverage), [measurement limits](../measurement.md#limits), README coverage/exit guidance and executable report-schema descriptions using the [historical missing-evidence rationale](../proposals/net-change.md#comparability-and-missing-evidence) as provenance.

**Review checkpoint.** Can an agent distinguish a known zero from failed parsing using documented fields alone? Record any remaining structured-container failure modes that the chosen solution cannot observe.

## S3 — Unify Typed Report and Schema Contracts

**Rationale.** At the research baseline, configuration schemas derived from typed models while measurement JSON and its handwritten schema had separate owners. A comparison schema must not introduce another independently maintained solution. The baseline report schema permitted negative counts and left some effective-policy structure unconstrained. A focused public-contract refactor makes saved reports a reliable input boundary while preserving valid existing output.

**Provenance.** [Configuration schema code](../../src/config/schema.rs), [report schema](../../src/report_schema.rs), [schema audit](../research/configuration-and-documentation.md#machine-interfaces-must-preserve-policy-and-uncertainty), and the proposal's [one contract mechanism](../proposals/net-change.md#one-contract-mechanism). Pygount's [independent JSON format version](https://github.com/roskakori/pygount/blob/v3.2.0/docs/json.md) is useful compatibility precedent.

- [x] Inventory version-1 shapes and field introductions across every existing release tag (`v0.1.0` through `v0.1.6`) plus the S1b shape, including root/workspace, headline/full, optional/null fields, omitted zeros, file detail and effective policy. Source inspection shows `metadata.modules` first appears in v0.1.2; older exports lack required comparison evidence and are deliberately ineligible, rather than corrupt reports.
- [x] Add synthetic compatibility fixtures for each tag's supported variants before replacing manual construction; document their schema-validity and comparison-eligibility expectations separately. Add rejection tests for negative counts, invalid variants, duplicate identities in array rows and conflicting totals.
- [x] Give serialization, deserialization, structural schema and field descriptions shared typed public owners through the existing `schemars` mechanism. Share definitions only when shape and meaning agree.
- [x] Preserve valid version-1 output and document validation tightening; explicitly decide any incompatible S1 representation change rather than hiding it in this refactor.
- [x] Centralize headline projection. Keep internal aggregation types separate where their semantics differ; do not create a generic schema/plugin framework.
- [x] Implement semantic validation as an internal API exercised by tests; its public consumer is S4 `compare` input errors. Do not add a `validate` command. Check arithmetic, array-row identity uniqueness, coverage and totals supported by available detail, with full-input eligibility distinguishable from ordinary report validity.
- [x] Limit the duplicate-identity rejection guarantee to array rows. Dynamic-map duplicate JSON keys are collapsed by the existing deserializer, with the last value retained; schema validation cannot recover them. Document and test that boundary instead of promising duplicate-aware parsing. A stricter reader would require a separate decision.
- [x] Describe nonnegative ranges, missing versus zero, language-participation file counts, additive embedded rows, and effective-policy structures in self-contained schemas with valid examples.

**Completion check.** Current valid measurement output retains its documented shape; per-release fixtures establish historical compatibility and intentional comparison exclusions. Actual root/workspace outputs validate against generated schemas; internal validation tests assert specific structural/semantic errors. Missing historical failure evidence survives decoding distinctly from recorded empty evidence. Config parsing, report serialization and schema generation agree without copies of field contracts. Tests, formatting and lint pass; run the private regression if measurement behavior changes.

**Documentation in this stage.** Update executable schema descriptions, [report contract](../PRODUCT.md#reporting-and-coverage) and README automation examples using the [historical compatibility requirements](../proposals/net-change.md#accepted-inputs-and-identity) as provenance. **Review checkpoint.** Can an agent learn structure and semantics from the executable schemas alone? Check that the refactor has not silently broadened supported inputs or changed counts.

## S4 — Implement Aggregate and Topology Net Change

**Rationale.** Comparing saved measurements directly serves the owner's workflow and works without source checkouts. A useful result preserves before/after counts and explains workspace composition, package detection and coverage changes. Removing a root from configuration must not look like proven source deletion. Removing a counted descriptor can reduce all-counted totals and reclassify retained source while source LOC stays unchanged. Zero aggregate change can conceal significant arrivals, departures or reclassification.

**Provenance.** [Net-change proposal](../proposals/net-change.md), [comparison research](../research/net-change-tools.md), cloc's [source comparison](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L3190), and scc's [history analysis](https://github.com/boyter/scc/blob/v4.1.0/processor/history.go). The peers demonstrate adjacent capabilities, with different semantics.

- [x] Review the proposal against S1/S3 outcomes and record decisions on remaining public-interface recommendations. Recommended initial scope: aggregate/topology comparison; optional per-file comparison deferred to its own decision. Resolve headline size before coding the projection: prefer fixed-size presence summaries by entity kind and direction with complete rows/findings in the full output, so a restructure cannot flood the compact headline. Preserve visible zero-net changes; define the summary shape and schema together.
- [x] Add failing tests for full-report eligibility, direction, version/mode incompatibility, arithmetic overflow and destination aliases before implementing the relevant behavior.
- [x] Implement `after - before` using checked arithmetic and one comparison model; never reload source, current config or ignore files.
- [x] Match the union of recorded identities and represent member/folder/package presence explicitly. Use existing modules as package evidence; package rows must not double-add their folder counts.
- [x] Separate changes in matched roots from contributions of entering/leaving roots; preserve zero-count member changes and disjoint nonempty workspaces.
- [x] Emit stable structured findings for recorded policy, counter, identity, module, coverage and presence differences, including S1 failures and missing historical failure evidence. Absence of findings is not proof of source-only change; old successful reports do not certify notebook correctness.
- [x] Expose the self-contained comparison schema through the shared generation mechanism, with semantic descriptions and examples.
- [x] Render terminal, Markdown and JSON from the same result, preserving findings and consistent totals in headline/full forms.
- [x] Verify self-comparison, reversal, ordering independence, zero-net replacements, reclassification, nested-folder non-additivity, descriptor removal, coverage-only paths and incomplete measurements.

**Descriptor-removal oracle.** Use a three-line `package.json` (`{`, a `"name": "example"` property, `}`) and two nonblank JavaScript statements in `src/index.js`, without classification overrides. Removing only the descriptor changes `all_counted` code/lines from 5 to 2 and files from 2 to 1; source code/lines stay 2 and source files stay 1. Production source code changes 2 to 0, unclassified source code 0 to 2, the npm module departs, and the root/source folder remains. Package departure is not an additional LOC subtraction. This synthetic result was reproduced on the unchanged research-baseline source during review follow-up.

**Completion check.** Satisfy the historical S4 [acceptance criteria](../proposals/net-change.md#acceptance-criteria-and-decisions), including compatibility with eligible old full exports and no conversion of unavailable counts into known zero. All required formats agree. Tests, formatting and lint pass; run private regression if shared measurement behavior changes. No Git execution, rename detection, empty-directory inventory, percentage metrics or history store is required.

**Documentation in this stage.** Move shipped behavior into [PRODUCT.md](../PRODUCT.md); add README recipes for single-root/workspace comparisons, arrivals/departures and partial coverage; update schema descriptions and [measurement limits](../measurement.md). Retain the implemented design as a historical decision record and move deferred scope into conditional follow-ups. Resolve stale product exclusions in the same change.

**Review checkpoint.** Can a reader distinguish recorded LOC changes, configuration changes and workspace membership changes? Assess whether aggregate/topology output answers the original workflow before deciding on optional per-file detail.

## S5 — Add a Focused Selection Explanation

**Rationale.** This is the strongest optional usability recommendation because it helps establish trustworthy scope. Existing rule IDs and review findings provide ingredients; a path-focused explanation can connect why a file was excluded, unrecognized, assigned a parser or purpose, or associated with a module convention. The original Handlebars investigation demonstrates the need to understand the counted input. Peer diagnostics establish an interface precedent, not measured demand.

**Provenance.** cloc's [found/counted/ignored and filter diagnostics](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L2310), [Locmetry findings](../../src/report.rs), and the [research recommendation](../research/tool-lessons-and-gaps.md#evidence-can-improve-scope-without-silently-changing-totals).

- [x] Write a bounded public contract using synthetic debugging cases: ignored path, project exclusion, unrecognized extension, mapped parser, first-match classification, module inference and parse failure.
- [x] Prefer a targeted path workflow if it answers those cases without inventorying every pruned file; decide the command and machine output only after that assessment.
- [x] Preserve shared configuration discovery, matching and counting behavior. Explain the actual decision rather than reimplementing it in a diagnostic path.
- [x] Expose known reasons and missing evidence, with stable machine semantics where needed. Do not infer a cause the traversal never recorded.
- [x] Add failing behavior tests before implementation, including single-root/workspace path bases, personal defaults and rule ordering.

**Completion check.** The documented workflow answers each agreed debugging case, with a reason consistent with ordinary measurement and no silently different scope policy. Required checks pass; assess private regression if shared measurement paths change.

**Documentation in this stage.** Add a task-focused troubleshooting guide if the workflow outgrows README usage, link it from the README, and update the product/schema contract for any public interface. Include complete examples using the executable's real output.

**Review checkpoint.** Assess against the agreed debugging tasks. If available evidence cannot support the proposed explanation, narrow the promise or revise the design explicitly before shipping it.
