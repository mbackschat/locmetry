Verification added three measures beyond the design below: a `.gitattributes` keeps text checkouts on LF, because CRLF checkouts broke documentation tests and would have shipped CRLF guides; subfolder paths in messages are rebuilt with the platform separator; and a pull request that changes the release workflow builds every archive without publishing. The optional scope moved to [DEFERRED](../../DEFERRED.md#windows).

The sections below preserve the reviewed design and acceptance criteria. Their imperative wording, examples and stated limitations are historical evidence, not current guarantees. Do not update this body to track behavior; this record carries no live scope.

## Problem

Locmetry releases only macOS arm64 and Linux binaries, while the line counters it is compared with all run on Windows: Tokei ships Windows binaries and Scoop/winget packages, scc's release configuration builds Windows, and cloc ships a Windows executable ([tool comparison](../../research/tool-capability-comparison.md)). Windows users can run the Linux binary under WSL, but not natively from PowerShell.

## Contract

Windows x86_64 becomes a supported platform. PowerShell is the supported Windows shell; `cmd.exe` receives no guidance.

| Area | Guarantee on Windows |
| --- | --- |
| Distribution | Each release adds `locmetry-VERSION-x86_64-pc-windows-msvc.zip` with `locmetry.exe`, the Bash helper, `LICENSE` and `THIRD-PARTY-NOTICES.md`, covered by `SHA256SUMS`. The C runtime is linked statically, so no Visual C++ redistributable is needed, matching the static Linux builds. |
| Paths in reports | `metadata.root`, member roots, configuration paths and the human `Root:` footer use ordinary drive paths such as `C:\work\app`, never the verbatim `\\?\C:\work\app` form that `canonicalize` returns. Root-relative paths keep `/` separators on every platform. |
| Personal defaults | `$XDG_CONFIG_HOME\locmetry\config.toml` when `XDG_CONFIG_HOME` is absolute, else `%APPDATA%\locmetry\config.toml`. Tokei, cloc and uv use the same Roaming folder. One location only, so `metadata.user_config_path` stays unambiguous. |
| Terminal styling | Locmetry enables virtual-terminal processing on the console; when the console refuses, output is plain, as with `--no-color`. |
| Saved reports | `compare` accepts reports encoded as UTF-8, UTF-8 with a byte-order mark, or UTF-16 with a byte-order mark, which Windows PowerShell 5.1 writes for `>` and `Out-File`. Locmetry itself always writes UTF-8 without a byte-order mark; documentation recommends `--output FILE`. |
| Comparison overwrite guard | `compare --output` refuses a path that is the same file as an input, including hard links, on every platform. |

macOS and Linux behavior is unchanged.

## Required

- A Windows runner in the CI test matrix, and the Windows target in the release workflow, release checks and licence notices.
- The four behavior changes in the table: paths, personal defaults, terminal styling and comparison input/guard.
- README installation and PowerShell usage notes: quoting globs in single quotes, `--output` instead of `>`, and where personal defaults live. PRODUCT and the affected guides state the Windows guarantees.

## Optional

- A Scoop manifest in a bucket repository, updated per release like the Homebrew tap.
- PowerShell equivalents of the `jq` recipes in the cookbooks.
- PowerShell tab completion, generated by clap together with the other shells.
- Accepting UTF-16 configuration and workspace files, which PowerShell 5.1 writes for `>` as well.

## Excluded

- `aarch64-pc-windows-msvc`: Windows on ARM runs the x86_64 binary through emulation.
- `cmd.exe` guidance, MSI installers and winget manifests.
- Running the Bash and Python development scripts on Windows; they stay Unix-only tooling.

## Feasibility Risks

- Every dependency is pure Rust, so the Windows build needs no C toolchain beyond the MSVC linker on the runner.
- Tests that rely on Unix permissions or on file names Windows forbids, such as `:` and `\`, stay Unix-only.
- Glob matching, `.gitignore` handling and CRLF line endings are exercised only by the Windows CI job; its first runs set the remaining work list.
