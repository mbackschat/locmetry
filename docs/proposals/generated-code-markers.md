## Problem

Module layouts claim every file in a source folder as hand-written implementation, including generated code: Polar's SDKs, Jellyfin's and Bitwarden's EF Core migrations, gin-vue-admin's generated Go and Loki's protocol buffer code. The [generated-code measurements](../research/generated-code-markers.md) of 2026-10-23 found documented markers on 7–37% of module-claimed production in four of ten applications, and on 83–84% in two more, mostly EF Core designer files and vendored Go. Nothing in the report says so; a policy author finds it only by reading file headers or the largest-module-files list.

## Design

**Required: markers refine module claims.** A source file that a module layout would classify as `production` with category `implementation` instead gets category `generated` when it carries one of the markers below. Its purpose stays `production`, so totals, Test/prod and module credit do not change; the category makes it visible in `--show-categories`, `--table-category` and per-file records. Overrides, conventions and rules run earlier and keep deciding their files, so a policy that already classifies generated code, such as Immich's `other:generated` overrides, is unaffected, and generated test fixtures stay tests.

| Marker ID | Applies to | Matches | Basis |
| --- | --- | --- | --- |
| `go-generated-header` | Go source | A line matching `^// Code generated .* DO NOT EDIT\.$` before the first line that is neither blank nor a comment | [`go help generate`](https://pkg.go.dev/cmd/go#hdr-Generate_Go_files_by_processing_source) |
| `roslyn-generated` | C# and Visual Basic source | A file name ending `.designer`, `.generated`, `.g` or `.g.i` before the extension, ignoring case, or starting `TemporaryGeneratedFile_`; or a leading comment containing `<auto-generated` or `<autogenerated` | Roslyn's `GeneratedCodeUtilities`, which the .NET analyzers use |
| `java-generated-annotation` | Java source | `@Generated` from `javax.annotation.processing`, `javax.annotation` or `jakarta.annotation`, by qualified name or import, annotating the first top-level type; annotations on members do not count | [Java SE `Generated`](https://docs.oracle.com/en/java/javase/21/docs/api/java.compiler/javax/annotation/processing/Generated.html), whose documentation allows marking generated parts of a hand-written file |
| `linguist-generated` | Any source | A path a `.gitattributes` file in the scan root marks `linguist-generated`, with Git's precedence, `-linguist-generated` and `linguist-generated=false` unsetting it; the declaration is the project's judgment, which can be broad, as Saleor's covers hand-written data migrations, and a rule overrides it | [GitHub's attribute](https://docs.github.com/en/repositories/working-with-files/managing-files/customizing-how-changed-files-appear-on-github) |

```json
{"path": "sdk/python/polar/__init__.py", "purpose": "production", "category": "generated", "rule": "builtin:linguist-generated", "module": {"path": "sdk/python", "detector": "python"}}
```

- `rule` names the marker as `builtin:<marker>`, so `summary.largest_module_files`, which lists only files a layout decided, now shows the largest hand-written files. `explain` shows the matched line, or the `.gitattributes` file and pattern.
- Markers form a version-1 set, which a release may extend, recorded in the effective configuration as `builtin_generated_markers`; `classification.builtin_generated = false` switches them off.
- Leading comments are read after a byte-order mark, which EF Core writes; reading stops at the first line that is neither blank nor a comment.

**Required: the `dotnet-generated` convention becomes the `roslyn-generated` marker** before its first release. As a convention it runs before rules, so a policy cannot reclassify designer files with a rule, and its case-sensitive `*.Designer.cs` misses Visual Basic and lowercase names. Roslyn's comment check also finds the EF Core model snapshots, which the convention matches by name.

**Optional**, each measured in one application. Deferred by the owner on 2026-10-23:

- `django-migration-header`: `# Generated by Django ` on the first line of a Python file, as Django's migration writer emits it. Saleor: 44,770 lines, 17% of its module production. Defer: the header stays when developers add code, and 15,540 of those lines are migrations with hand-written data functions.
- `openapi-generator-files`: paths listed in an `.openapi-generator/FILES` manifest, relative to its parent folder. Halo: 21,459 lines, exactly its generated API client. Defer: precise in Halo, but the generator documents the file only in a log excerpt, so its format is no contract; a `.gitattributes` declaration or a rule covers the client.
- `@generated` in the leading comment, Meta's convention, and Relay's `__generated__/` folders: precise in Relay's repository and in vendored code, but not observed in an application's own source. Defer until it is.
- Tool-specific headers from GitHub Linguist, such as the protocol buffer compiler's and swag's: no match in the applications except swag's in Answer, 13,491 lines, and jOOQ's. Defer; add a header only with measurements of its own. jOOQ's header claimed a hand-written class whose author copied it, and in Linguist's two-line position it matches no application file.

**Excluded:**

- Free-text heuristics, such as "generated" near "do not edit": they claimed hand-written production in sqlc, protobuf-go and gopls. Linguist's looser Go check, any `// Code generated` line in the first 40 lines, claimed gopls's hand-written generator.
- MyBatis Generator's `@mbg.generated` tag, which marks elements rather than files, claimed the generator's own source, and is absent from mall's generated code.
- Naming a generator in a header, such as OpenAPI Generator, which claimed Immich's hand-written SDK script.
- Changing the purpose. Generated code is shipped and often maintained; a project that counts it as Other says so with an entry, as Immich does. The deferred [generated and minified evidence](../plans/measurement-quality-and-net-change.md#conditional-follow-ups-and-preserved-rationales) keeps its rationale: generated does not mean disposable.
- Files no module layout claims. Unclaimed files are already listed for review, and entries, conventions and tests decide the rest.
- Generators without a documented marker, such as mall's MyBatis output and Immich's SQL snapshots: they need policy entries.

## Feasibility

Classification so far reads only paths. Markers read the leading comment block of Go, C# and Visual Basic files that a module layout claims, and the declarations before the first top-level type of Java files, skipping balanced annotation arguments, a bounded read that measurement already performs for inline Rust tests, and parse `.gitattributes` files inside the scan root; subfolder measurement reads them from the whole project, like module context. Module credit by layout coverage already credits files whatever decided them, so modules keep their credit. Reports of earlier producers simply lack the new rule IDs.

## Acceptance

- Fixtures: a module-claimed Go file with Go's line is `production:generated` with `builtin:go-generated-header`; the same line after the `package` clause, or `// Code generated` without `DO NOT EDIT.`, stays implementation; a `*.designer.vb` file and a C# file with a byte-order mark and `// <auto-generated />` are generated; a Java class annotated `@jakarta.annotation.Generated` after an annotation whose arguments contain braces is generated, while `@Generated` on a method only, or one imported from another package such as `lombok`, leaves the file implementation; a `.gitattributes` pattern marks files generated and a later `-linguist-generated` unsets it; a rule-decided or test file with a marker keeps its decision.
- Module credit is unchanged, and `summary.largest_module_files` omits marker-decided files.
- On the commits in the [measurement record](../research/generated-code-markers.md), the reclassified code matches the record's documented column, and the generators' repositories gain no generated file outside those the record lists as generated.
- PRODUCT, the README, the configure guide, both schemas and the changelog describe the markers; the `dotnet-generated` convention is gone from them.
