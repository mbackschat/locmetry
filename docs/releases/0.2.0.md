# locmetry 0.2.0

This minor release adds saved-report comparison, path explanations and project-aware subfolder measurement. It also corrects notebook and Handlebars counting and makes unavailable counts visible.

## New capabilities

- **Net change:** `locmetry compare before.json after.json` reports signed aggregate changes and the presence of roots, modules and folders in saved full reports. It works without the measured projects. JSON, Markdown and terminal views preserve coverage and policy evidence. Per-file comparison remains deferred.
- **Path explanations:** `locmetry explain src/main.rs` explains selection, classification and counting for one file using the measurement policy.
- **Subfolder measurement:** `locmetry . --subfolder packages/core/src` keeps project configuration and module context while limiting counts and coverage to the chosen directory. Paths stay project-relative. Filtered targets fail clearly, and comparison requires identical restrictions.
- **Positional directories:** `locmetry path/to/project` works alongside `--root`. Existing subcommand names retain precedence; use `./compare` or `--root compare` for a directory named `compare`.
- **Human output:** compact headers, muted legends, semantic colors and useful subtree folder rows improve terminal readability. Redirected output and JSON remain free of styling escapes; Markdown uses portable emphasis.

## Measurement and contract corrections

- Notebook containers are decoded once, with Tokei counting individual code cells. Markdown, fenced Markdown and raw-cell text are counted once, and supported notebook shapes no longer silently become zero counts.
- Readable content that cannot be parsed or decoded is recorded in `parse_failures`, separate from unreadable files. Backend inaccuracy produces exit 2. Handlebars counting respects template syntax and distinguishes decoding from access failures.
- `.gitmodules` hints handle quoted values, comments, continuations and named sections without running Git or following includes.
- Shared typed contracts generate report and comparison schemas. Saved-report validation checks arithmetic, identities, language participation and module contributions before comparison. `locmetry --schema comparison` describes comparison structure and semantics.
- README troubleshooting queries and CI workflows are executable checks. Documentation separates supported contracts from historical design records.

## Compatibility and upgrading

Configuration and measurement report schema versions remain `1`. New report evidence is additive, but older strict readers may reject it. Consumers must inspect `metadata.scope.subfolder` before treating summary values as whole-project totals. Historical omissions remain distinct from recorded empty evidence; see [saved-report compatibility](../report-compatibility.md).

Counting corrections can change measured totals even when source files are unchanged. Comparison reports a producer-version change, but cannot reconstruct corrected counts from an old export. Regenerate baselines with 0.2.0 when comparing source changes alone. Early development exports mislabeled as 0.1.6 cannot be distinguished from the old release by version alone.

Install or upgrade with `brew install mbackschat/tap/locmetry` or `brew update && brew upgrade locmetry`. Release archives include third-party notices and SHA-256 checksums for macOS arm64 and static Linux x86_64/aarch64 executables. See [installation](../../README.md#install) and the [supported product contract](../PRODUCT.md).
