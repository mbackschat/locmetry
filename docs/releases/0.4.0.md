# v0.4.0 — Output Routing and Embedded Guides (Unreleased)

Implemented in development as `0.4.0-dev.1`; v0.3.0 remains the stable release. This is a record of changed commands, not a publication announcement. [PRODUCT](../PRODUCT.md#output-routing) owns the contract. No deprecation release or transition flags are planned.

## Breaking CLI changes

`--output FILE` writes only that file, with no stdout. `--format` controls its contents; without an explicit format, exports use full JSON. `--output -` selects stdout with the same rules. File extensions do not select formats, and saved human output is unstyled.

`json` now means the complete document everywhere. `headline` explicitly selects compact JSON for measurement, workspace and comparison. Ordinary pipes still default to headlines and ordinary terminal runs to tables. Explanation keeps complete JSON in pipes and has no headline or `--output` option.

| Task | Command or adjustment |
| --- | --- |
| Save a comparison-ready baseline silently | `locmetry service --output before.json`; remove the old redundant `> /dev/null`. |
| Request compact JSON explicitly | Use `--format headline` instead of `--format json`. Full JSON includes more configuration, breakdown and coverage detail. |
| Inspect a saved result | Read the file afterward, e.g. `jq .summary before.json`; stdout after `--output FILE` is empty. |
| Save a Markdown comparison | `locmetry compare before.json after.json --format markdown --output result.md`. |
| Save an adaptive table | `locmetry service --folder-rows 12 --format table --output folders.txt`; it no longer also saves full JSON. |
| Include per-file records | `locmetry service --files --output before.json` or `--files --format json`. Human and headline formats now reject `--files`. |
| Save a schema | `locmetry --schema report > schema.json`; schema queries reject all explicit measurement/presentation arguments and roots. |

In measurement, explicit ineffective `--categories` and `--depth` options warn on stderr, preserving the result and exit status. Defaulted depth stays silent. Help wraps descriptions to terminal width with proper continuation indentation.

`--schema` is now a standalone query. Previously ignored roots, selection and sort settings now fail with exit 1; explicit schema `--categories`/`--depth` also fail instead of warning. Implicit defaults remain valid, and schemas do not load project or personal configuration.

## Embedded task guidance

Start project configuration with `locmetry --guide configure`. The `selection`, `reports` and `compare` topics provide focused workflows, examples and caveats from the installed binary, without a skill or network access. Root and subcommand help provide next commands. Guides share schema queries' standalone argument rule and print unchanged Markdown with source/version identification. Existing troubleshooting and detailed README recipes now live in the same guide sources that the binary embeds.

Configuration advice now permits evidence-based rules, deliberate unclassified decisions with reasons, or unresolved questions; it no longer asks agents to eliminate every unclaimed finding. Counting and classification rules themselves are unchanged.

## Preserved behavior and limits

Counting and JSON schema version 1 are unchanged. Historical headline `report` pointers remain readable and round-trip; new output omits them. Existing full exports stay comparable, and `--files --output -` still works. Destination protection and partial-result exit 2 remain in effect for file exports. Informational findings stay in the saved result; warnings and errors stay on stderr.

A producer-version difference can cause `counter_changed` even though this batch changes no counting rules. A headline cannot reconstruct a full historical baseline. Separate measurements are not guaranteed to observe the same filesystem state; shell redirection and `tee` bypass destination protection and need pipeline status handling. No dual-output option or saved-measurement renderer is added. Conditional features remain deferred.
