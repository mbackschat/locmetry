# Comparable Tools Inform Net Change Design

Research date: 2026-10-15. **Saved-report net change has a direct public precedent, and the research supports Locmetry's proposed scope.** EntropyX compares saved code-metric snapshots; cloc compares source content; scc analyzes Git history; Tokei accumulates saved counts. Enola, an adjacent architecture tool, supplies a useful distinction between comparison warnings and policy gates. Locmetry's value should therefore be framed as comparing portable, classified measurements with explicit membership and coverage semantics, not as inventing code evolution analysis. The findings reinforce the [net-change proposal](../proposals/net-change.md) and identify focused acceptance cases without justifying additional features.

A capability not established in these surfaces is not necessarily absent from every extension or repository branch. This extends the earlier [counting-tool research](loc-counting-tools.md).

## Net totals cannot establish arrivals or unchanged content

EntropyX makes the most useful caution concrete. Its console assessment describes the difference between aggregate file counts as files added or removed, while separate HTML helpers calculate new and removed paths through set differences. These are different quantities. **For `{a,b} → {a,c}`, the net file count is zero, but one path enters and another leaves.** The distinction follows from the inspected code; this scenario was not executed against EntropyX. [Assessment](https://github.com/drcircuit/entropyx/blob/545e8b44e7cf85a772de33ad9d17ee8980c2cb03/src/CodeEvo.Reporting/ComparisonReporter.cs#L235), [path helpers](https://github.com/drcircuit/entropyx/blob/545e8b44e7cf85a772de33ad9d17ee8980c2cb03/src/CodeEvo.Reporting/ComparisonReporter.cs#L396)

For Locmetry, the inference is to guard this replacement scenario for folders, detected packages, and workspace roots, plus files if optional detail is implemented. Equal-sized entering and leaving roots must remain visible even when total LOC and member count stay constant. A package detector disappearing is likewise different from source deletion. The proposal already models these distinctions; a named replacement acceptance case would make accidental suppression harder.

cloc's source alignment illustrates why matching needs an explicit contract. Its directory algorithm aligns remaining paths after stripping leading directories and forcibly pairs exactly one file on each side; its Git path uses rename statuses. Those choices rely on evidence or assumptions outside saved-count comparison. Locmetry should retain member-name and relative-path matching, disclose identity limits, and avoid inferred renames. Zero net LOC also cannot mean unchanged content or zero churn. [Directory alignment](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L13725-L13829), [Git alignment](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L13830-L13906)

## Missing evidence must survive serialization and rendering

EntropyX's inspected parser defaults absent numeric properties to zero and missing file arrays to empty. That makes permissive ingestion possible but can turn missing evidence into plausible shrinkage. scc offers a useful contrasting detail: optional cognitive metrics are omitted when disabled but serialized at zero when enabled. Locmetry should preserve its proposed distinction between omitted aggregate zeros, unavailable measurements, and missing required sections. [EntropyX parser](https://github.com/drcircuit/entropyx/blob/545e8b44e7cf85a772de33ad9d17ee8980c2cb03/src/CodeEvo.Reporting/ComparisonReporter.cs#L35), [scc structures](https://github.com/boyter/scc/blob/v4.1.0/processor/structs.go)

Coverage must also travel with the result. cloc documents skipped files on diff timeout; the inspected diff JSON renderer receives counts rather than the error collection, while errors are printed separately and quiet mode can suppress them. Tokei's serialized language model retains an `inaccurate` flag, although its machine-output branch returns before the terminal warning. The lesson is to carry structured coverage findings into full JSON, headlines, terminal tables, and Markdown rather than relying on stderr alone. [cloc options](https://github.com/AlDanial/cloc/blob/v2.10/README.md#options), [JSON renderer](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L3712-L3845), [error handling](https://github.com/AlDanial/cloc/blob/v2.10/cloc#L1526-L1556), [Tokei model](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/language/mod.rs), [entry point](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/main.rs)

Typed serialization is useful but insufficient for agent discovery. scc's `json2` is another output shape, not an in-document schema version. No discoverable report-schema command was established in the inspected counter CLI and serializer surfaces. Locmetry should retain a separate versioned comparison contract and self-contained `--schema comparison`, generated from the same described public types used for serialization. Arithmetic and identity validation still require semantic checks. [scc serializers](https://github.com/boyter/scc/blob/v4.1.0/processor/formatters_json.go)

## Classification and provenance remain separate dimensions

scc supports pattern-based categories such as `Ruby Spec`, backed by Ruby counting rules, with first-match precedence. This is useful prior art for test separation, but a named language bucket differs from retaining language and purpose independently. Locmetry should guard a classification transfer that leaves total LOC unchanged while moving counts between production and test. Likewise, Tokei's primary and embedded-language representations reinforce the need to distinguish physical files from language participation instead of summing all nested counts. [scc category mapping](https://github.com/boyter/scc/blob/v4.1.0/README.md#counting-files-as-a-custom-category), [Tokei aggregation](https://github.com/XAMPPRocky/tokei/blob/v15.0.0/src/language/mod.rs)

Enola explicitly warns that changed extractors, exclusions, or tool versions can produce differences unrelated to edited source. Its snapshot fingerprints and provenance receipts provide stronger evidence than Locmetry's existing reports, but adopting them would expand this feature. The bounded lesson is to retain before/after provenance and stable findings while distinguishing **descriptive comparison from a policy gate**. Locmetry can show measured deltas despite recorded policy differences without claiming comparable settings prove source-only growth. Its proposed incomplete-coverage exit semantics remain separate from that decision. [Enola comparability](https://github.com/enola-labs/enola/blob/4178ed7f480e5bcce94a4c51826ded5a400ea86a/docs/SNAPSHOTS.md#two-values-compare-only-if-they-were-made-the-same-way)

## Carry focused guards into the proposal

The research does not require reversing a proposed decision. It adds three concrete guards worth naming: balanced entity replacement with zero aggregate change; a structurally incomplete report rejected instead of interpreted as shrinkage; and coverage findings preserved in every output form, including compact headlines. The existing classification-transfer and embedded-language reconciliation criteria should remain explicit. Schema-only examples should include the balanced workspace replacement so agents learn that presence and arithmetic answer different questions.

Keep one computed comparison result and three renderers. EntropyX shares its assessment routine but still calculates numeric changes inside renderer code; this supports the proposal's stronger separation without justifying a generic rendering framework. Git traversal, quality verdicts, history storage, charts, and new reproducibility fingerprints remain excluded. [EntropyX reporter](https://github.com/drcircuit/entropyx/blob/545e8b44e7cf85a772de33ad9d17ee8980c2cb03/src/CodeEvo.Reporting/ComparisonReporter.cs)

This was a selective primary-source review, not a benchmark or exhaustive market survey. Enola's behavior was assessed from documentation, and commit dates alone establish neither maturity nor support. No quantitative maintenance-cost or return-on-investment claim follows. The evidence strengthens the feature's practical rationale while narrowing its claim: trustworthy interpretation of saved Locmetry measurements, with topology, classification, and uncertainty preserved.
