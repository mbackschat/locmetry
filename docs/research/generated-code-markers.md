# Generated-Code Markers

Measured 2026-10-23 with the development build of Locmetry 0.9.0 at commit `f413a59` (`--no-user-config`, release build) on shallow clones, removed afterwards. Question: which signals identify generated code inside module layouts without false claims, so that it no longer counts silently as hand-written implementation? The [framework layout precision pass](framework-layouts.md#shared-false-claims-not-specific-to-a-row) found such code to be the largest silent false claim; the [prior-art record](classification-prior-art.md#generated-code) chose GitHub Linguist's checks as the starting evidence. The [generated-code markers proposal](../proposals/generated-code-markers.md) uses these results.

## Method

A script read the leading comment block of every source file Locmetry reported (the lines before the first line that is neither blank nor a comment) and its first 30 to 60 lines, and evaluated each candidate signal separately. Two groups of repositories were measured:

- **Applications with known generated code**, for coverage: [macrozheng/mall](https://github.com/macrozheng/mall) `dcaa93b31503`, [halo-dev/halo](https://github.com/halo-dev/halo) `6745dd2f85de`, [apache/answer](https://github.com/apache/answer) `6744295fa888`, [flipped-aurora/gin-vue-admin](https://github.com/flipped-aurora/gin-vue-admin) `f7f1009c98e6`, [polarsource/polar](https://github.com/polarsource/polar) `ad44441b7edf`, [saleor/saleor](https://github.com/saleor/saleor) `ec535e23e86b`, [grafana/loki](https://github.com/grafana/loki) `be73bce830ab`, [jellyfin/jellyfin](https://github.com/jellyfin/jellyfin) `c7ce6a1b56ee`, [bitwarden/server](https://github.com/bitwarden/server) `9ef685395cfe`, and the Immich showcase at `v3.3.4`.
- **Generators' own repositories**, for false claims, because their hand-written source contains the marker strings as templates and constants: [golang/tools](https://github.com/golang/tools) `02c9e4cb4c2f`, [protocolbuffers/protobuf-go](https://github.com/protocolbuffers/protobuf-go) `df958731cf19`, [grpc/grpc-go](https://github.com/grpc/grpc-go) `6ce1c873d713`, [sqlc-dev/sqlc](https://github.com/sqlc-dev/sqlc) `1911a764fc85`, [django/django](https://github.com/django/django) `8e4e95da9b5b`, [mybatis/generator](https://github.com/mybatis/generator) `fb608f72d390`, [facebook/relay](https://github.com/facebook/relay) `ffd22c5f4d1c`, [swaggo/swag](https://github.com/swaggo/swag) `eb131898e464`, [ent/ent](https://github.com/ent/ent) `8037bc89bcab`, and, added the same day for .NET, [dotnet/efcore](https://github.com/dotnet/efcore) `dc5f6f32df2f` and [CommunityToolkit/dotnet](https://github.com/CommunityToolkit/dotnet) `b135626dd54d`.

Hand-written lists served as oracles: the `generated` rule of the [Loki policy](policy-test-drives/policies/loki.policy.toml) and the generated overrides of the [Immich policy](../../examples/showcase/immich/overlay/.locmetryrc).

## Coverage in applications

Code lines of production that module layouts claim, and the share the signals would reclassify. "Documented" is Go's line, Roslyn's rule and `.gitattributes`; "with optional" adds Django's header, OpenAPI Generator's manifest, `@generated` and `__generated__/`.

| Application | Module production | Documented | With optional |
| --- | ---: | ---: | ---: |
| mall | 65,451 | 0% | 0% |
| Halo | 131,956 | 0% | 16% |
| Answer | 99,681 | 1% | 1% |
| gin-vue-admin | 69,465 | 13% | 13% |
| Polar | 576,106 | 37% | 37% |
| Saleor | 259,334 | 7% | 18% |
| Loki | 3,563,852 | 84%, of which 2,857,043 lines in `vendor/` | 84% |
| Jellyfin | 217,302 | 26% | 26% |
| Bitwarden | 1,251,248 | 83% | 83% |
| Immich | 169,786 | 0% | 0% |

- Against Loki's hand-written list, the documented signals find 50 of its 51 files, 130,084 of 130,204 lines. The one miss, `tools/doc-generator/main.go`, is a hand-written generator listed by mistake. They also find four counterfeiter fakes, 2,590 lines, that the list omits.
- Immich's 38 hand-labelled files, 16,165 lines, carry no documented signal: the oazapfts SDK client has a free-form "DO NOT MODIFY" banner, and the SQL query snapshots a "NOTE: ... auto generated" comment.
- Answer's swag documentation, 13,491 lines, says "Code generated by swaggo/swag. DO NOT EDIT" after a `// Package docs` prefix and without the final period, so Go's line does not match; golangci-lint loosened its own check for such tools.
- Bitwarden's share is mostly EF Core designer files, which the unreleased `dotnet-generated` convention already classifies; Roslyn's comment check adds the model snapshots.

## Java and Spring

Measured the same day with the same build, because the first round covered Java only through mall and Halo. Repositories:

- **Spring and Java applications with committed generated code**, found through GitHub code search: [plantbreeding/brapi-Java-TestServer](https://github.com/plantbreeding/brapi-Java-TestServer) `e014b083545f` (Swagger Codegen), [KomMonitor/spatial-data-processor](https://github.com/KomMonitor/spatial-data-processor) `e12c81447bde` (OpenAPI Generator), [alipay/container-auto-tune](https://github.com/alipay/container-auto-tune) `289dd4be983a` and [killbill/killbill-qualpay-plugin](https://github.com/killbill/killbill-qualpay-plugin) `22683558e43c` (jOOQ), with mall and Halo at the commits above.
- **Generators' own repositories**, every Java and Kotlin file whatever classified it, 12,014 files: [google/dagger](https://github.com/google/dagger) `6b3a449a1fe4`, [immutables/immutables](https://github.com/immutables/immutables) `07edca38e1fb`, [hibernate/hibernate-orm](https://github.com/hibernate/hibernate-orm) `37616099b745` (`tooling/metamodel-generator`), [jOOQ/jOOQ](https://github.com/jOOQ/jOOQ) `26771fd3e928`, [mapstruct/mapstruct](https://github.com/mapstruct/mapstruct) `211b2be6205a`, [OpenAPITools/openapi-generator](https://github.com/OpenAPITools/openapi-generator) `a03c03d2ace1` (`modules`) and [protocolbuffers/protobuf](https://github.com/protocolbuffers/protobuf) `b9a7f688ced6` (`java`).

| Signal | Source | Result |
| --- | --- | --- |
| `@Generated` from `javax.annotation.processing`, `javax.annotation` or `jakarta.annotation`, by qualified name or import, annotating the first top-level type | [Java SE `javax.annotation.processing.Generated`](https://docs.oracle.com/en/java/javase/21/docs/api/java.compiler/javax/annotation/processing/Generated.html), which says the annotation can also mark generated parts of a hand-written file, so only the type position states the whole file | No false claim. Applications: brapi-Java-TestServer 254 files, 22,809 lines, 53% of its module production; spatial-data-processor 29 files, 3,716 lines, 67%; every match names Swagger Codegen or OpenAPI Generator in the annotation and is a model or API interface; whether developers edited them since was not checked against history. The hand-written classes beside them in the same packages carry no annotation. Generators: 135 matches, all MapStruct's expected-output fixtures; hand-written generator source in Dagger, Hilt and Hibernate that writes the annotation as text is not matched |
| The same annotation anywhere in the file | The same | Three more matches, all tests: two hand-written tests that contain the annotation in string literals, and one MapStruct fixture whose class annotation the measurement script missed because a later annotation argument contains braces; an implementation must skip balanced annotation arguments |
| jOOQ's header `This file is generated by jOOQ.` in the leading comment | Linguist `generated_jooq?`, which requires it in the first two lines | container-auto-tune 141 files, 26,421 lines; killbill-qualpay-plugin 9 files, 862 lines; jOOQ's own `jOOQ-meta` 184 files. False claim: container-auto-tune's hand-written `agent/twatch/ActionTemplate.java`, whose author copied the header. Linguist's two-line position matches none of container-auto-tune's files, because a license header precedes the line |
| Protocol buffer compiler's header | Linguist `generated_protocol_buffer?` | No match; Maven and Gradle generate protocol buffer classes into `target/` and `build/` |

- mall's MyBatis output and Halo carry no Java marker; jOOQ writes `@Generated` only when configured to, and container-auto-tune's jOOQ classes carry none.
- Most generated Java never reaches a measurement: Maven and Gradle generate into `target/` and `build/`, which projects ignore. The annotation matters for projects that commit generated sources, as both OpenAPI applications do.
- A copied header is a false claim no position rule prevents; it appeared once among 141 jOOQ matches and not among the Go and .NET matches.

## Conclusions

- A marker that records where a file came from does not show that nobody edited it since: Django's header stays on hand-written data migrations.
- Documented, position-bound markers made no false claim; every free-text heuristic did, including Linguist's own looser Go check. Generators' repositories are where marker strings occur in hand-written code, and only the position-bound checks survived them.
- `.gitattributes` declarations cover what no marker can, such as Polar's SDKs, and are the project's own judgment.
- Project-specific generators without a documented marker, as in mall and Immich, still need policy entries.
- Vendored code dominates Loki's markers; whether vendored generated code is production at all is the separate Go `vendor/` question in [PLAN](../PLAN.md).
