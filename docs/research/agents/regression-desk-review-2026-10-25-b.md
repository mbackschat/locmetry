The range is four commits and 8 files: the record of that review (`29ef293`, with its ledger row and index entry), the fixes for its findings N1 to N4 (`ebf347d`, `63334e4`) and the fix for R1 of this review (`361f8cf`). ## Verdict

No regression. Of 45 captured texts, 41 are unchanged from the control apart from timestamps: `-h` and `--help` of the root, `compare` and `explain`, `workspace -h`, the `help` subcommand, five of the seven guides, all six schemas, the version, and the table, folder-and-category table, `--verbose` table, Markdown, headline, full JSON and `--files` output of the synthetic fixture, the workspace output in both member styles with `--verbose` and as JSON, three `explain` outputs and all four completion scripts. Exit statuses and stderr are identical in all 45 for `63334e4`, and all 57 captures of `361f8cf` (the 45 texts and the 12 sections of the reports guide) exit 0 with empty stderr. The four that differ are `workspace --help`, the `reference` guide, the `reports` guide and the man page, and each difference is an intended one: the destination sentence of `workspace --help`, the three reference-guide passages (wrap width, destination, install recipe), the one reports-guide sentence and the man page's rendering of the first two.

`361f8cf` differs from `63334e4` in one line of one file, `docs/guides/reports.md`, which only `--guide reports` embeds. The `63334e4` captures had been deleted, so the other captures were not compared byte for byte again. Instead every help text, guide, schema, the man page and the four completion scripts of the new capture has exactly the size measured for `63334e4`, and the new reports guide is byte-identical to its header plus the tracked source.

All four findings of the previous review are fixed, R1 of this review is fixed, and each new factual claim matches the executable. Help wraps to the width of a terminal on stdout, stderr or stdin, otherwise to `COLUMNS`, else to 100, in all 22 runs tried, which combine pseudo-terminals on each stream with `COLUMNS` values. Workspace destinations behave as the help, the guide and PRODUCT now say, for root members and for project-folder members, in 21 cases. The install recipe succeeds on a clean `HOME`, twice in a row, where the control's recipe fails on all four redirects. All 51 guide and schema routes that help, guides, the README and the recorded guides name run, and every flag they name exists, apart from other programs' flags that the README and the showcase README quote. The new guard `help_wraps_to_columns_and_otherwise_to_100_columns` passes, as do all 94 selected tests on the `361f8cf` source.

What remains is small and unchanged by the last commit. The terminal precedence rests on dependency behavior no test locks (R2), and two edge values of `COLUMNS` are unstated (R3). Whether a subject's pseudo-terminal can change the help an agent reads is a benchmark question outside the range (R4). R2 to R4 stay open; this range does not change them.

No targeted agent run is needed. No text on an ordinary task's path changed apart from one sentence each in `workspace --help` and in the `choose-content-and-destination` section of the `reports` guide: root help, `compare` and `explain` help, `workspace -h`, the index and every other guide are unchanged. `workspace --help` grew 41 bytes, the `reports` guide 41 bytes and the `reference` guide 304 bytes in sections that only index routes request (`environment` +74, `files` +74, `man-page-and-completions` +156), far below what provider cache misses already swing in a four-pair median. The `reports` section is the one the index names for choosing report content and destination. It now reads 28 lines and 4,952 bytes, 41 of them new.

## Findings

Findings of the [previous review](regression-desk-review-2026-10-25.md#findings), checked against the candidate.

| Id | Result | Evidence |
| --- | --- | --- |
| N1 | Fixed | The `COLUMNS` bullet now says help wraps to the width of a terminal on stdout, stderr or stdin, otherwise to `COLUMNS`, else to 100. A pseudo-terminal with `TIOCSWINSZ` on the stream under test confirms it. Terminal on stdout, stderr or stdin alone, 70 columns, `COLUMNS=100` or unset: widest line 70 each. Precedence: stdout 70 beats stderr 90 beats stdin 80 beats `COLUMNS=60`. A 160-column terminal gives 160, so there is no cap. No terminal: `COLUMNS=60` gives 60, `COLUMNS=140` gives 140, unset gives 100. The share-bar clause is also exact: `COLUMNS` beats the terminal for bars in both directions (terminal 200 with `COLUMNS=60` puts the bars below the table, terminal 60 with `COLUMNS=200` beside it), and a pipe without `COLUMNS` falls back to 80. `terminal_size` 0.4.4 checks the three streams in that order on Unix and Windows alike. The guard `help_wraps_to_columns_and_otherwise_to_100_columns` passes, and its last assertion would fail on the control's bullet, which contains no 100 (read, not run). Edges in R3. |
| N2 | Fixed | The recipe now starts with `mkdir -p` for the four target folders. On a clean `HOME` it exits 0, writes the man page and the bash, fish and zsh completions (32,757, 12,458, 14,299 and 16,469 bytes) and runs again without error. The control's recipe fails each of its four redirects with "No such file or directory" and writes nothing. |
| N3 | Fixed | The `MANPATH` sentence now follows the install block directly and reads "If `man locmetry` finds no entry after installing the page, as on macOS", before the zsh sentence. On a clean `HOME`, `man -w locmetry` finds nothing, and finds the page, and still `ls(1)`, once `MANPATH="$HOME/.local/share/man:"` is set. `mandoc -T lint -W warning` is silent on the generated page, the bash script loads and registers `_locmetry`, and the zsh script passes `zsh -n` and registers under `fpath=(~/.zfunc $fpath)` with `compinit`. |
| N4 | Fixed | `workspace --help` says "Save outputs outside every member's root, which is the project for folders.", PRODUCT says the same twice and the Files bullet adds that members that are project folders share their project's root. Root members: output inside a member, in a new subfolder of a member, through `..` or through a symlink alias is refused with exit 1; beside the members in the project root, in an unrelated folder below it, beside the workspace file or elsewhere succeeds, and the same holds for repeated `--root`. Overwriting either workspace file is refused and leaves it unchanged. The control behaves identically, so only the text changed. |
