## Configuration and Categories

Requests from three projects categorizing their tests on 2026-10-24; the [policy entry review](proposals/archive/policy-entry-review.md) implemented the rest.

- Category groups with subtotals, such as a `law` group over several law categories, asked for by two projects and on 2026-10-25 by a third, a Lean project that computes estate shares over groups of categories in a script. `--table-category 'test:*law*'` already shows the selection's subtotal as the language table's Total, and `jq` over `summary.source_categories` computes a group in JSON. Reopen when a group subtotal is needed in JSON or several groups in one table.
- Categories of data files in tables. Full JSON `breakdown` has them, while `--show-categories` covers source. Reopen when fixture growth becomes a recurring review question, together with a decision on the source-only table contract. On 0.11.1 all three projects categorizing their tests again tallied data and documentation categories from JSON ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)), so the question recurs; the table-contract decision remains.
- Inline test hints in other languages, such as Lean `example` and `#guard` declarations in production files, reported like Rust's `inline_tests` without changing purposes. Reopen when a second Lean project asks.
- Content predicates on refinements, such as "mostly `theorem` declarations", which only change a category. Reopen after refinements ship, when a project's categories cannot be expressed by paths. Met on 2026-10-25: a12-rulekit defines test lanes by JUnit `@Tag` and bpmn-lean-experiment separates theorem files from definition files in one folder, both approximated by name globs. Both asked for content matching on refinements only, so file contents never move purpose totals. The [experiments](research/agents/experiments-2026-10-25.md#content-predicates-for-categories) set its scope: a regex that matches when any line matches covers the tag case, while counting declarations, as theorem-dominant mixed Lean files would need, stays out. It needs a proposal. On 0.11.1 both projects asked again, and in a field-sized synthetic project every one of seven agents read test sources for tags while four still labelled untagged unit tests by name ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)). bpmn-lean-experiment proposed a second design for the proposal to weigh: a category attribute in `.gitattributes` that the project's own tooling writes, read like `linguist-generated`, which covers files only counting declarations can classify but goes stale silently. Not proposed on 2026-10-26, a decision taken under the owner's delegation: the evidence above is about correctness, not efficiency. Agents read the sources for tags anyway, so a predicate would spare them wrong claims by name, not calls or reading. Propose it when wrong claims by name are the problem to solve, with an A/B that measures false claims as well as cost on the field-sized project.
- A display name on language mappings, so a mapping counted by another counter reports its own language, such as `.tsv` fixtures counted with the JSON counter as data and reported as TSV. Two projects asked on 2026-10-25 for such files to count as data rather than documentation. Mapping them to JSON already does that, at the cost of the reported name; a `kind` field alone would keep Plain Text's all-comment line split ([experiments](research/agents/experiments-2026-10-25.md#content-kind-of-mapped-files)). Reopen together with the display name for language corrections below, when a project needs the name. On 0.11.1 a12-rulekit's `.api` dumps and the private Lean project's TSV tables came up again, and three of seven agents in an experiment left a TSV unmapped because Plain Text would count it as documentation ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)).
- A refinement filter on the deciding rule, such as `decided_by = ["builtin:test-directory"]` for files in test folders without test cases, which today copies the convention's suffix list into `except`. One request on 2026-10-25; on 0.11.1 a12-rulekit and bpmn-lean-experiment both asked ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)), which meets the condition. It needs a proposal, best together with content predicates and entry references in `except`, since all three narrow what an entry matches.
- References to other entries in `except`, such as `except_entries = ["observation-bundles"]`, so an entry leaves out the files another one matches without copying its globs, which drift apart. bpmn-lean-experiment and the private Lean project asked on 0.11.1 ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)); the verbose note on entries that lost files to an earlier entry recommends an `except` list even for a deliberate catch-all, which causes the copies. It needs a proposal, together with the deciding-stage filter above.
- Reasons for unused patterns, such as a pattern whose only matches are symbolic links selection does not follow, which today reads as a typo. One request on 0.11.1 ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)). Reopen with a second.
- Orthogonal tags beside the category, which must not break the guarantee that categories add up to purpose totals. Reopen when a second project needs a second axis.
- Test/prod between two chosen categories rather than purposes. Reopen with a second request.
- `decision.also_matched` in `explain`, listing the entries that match a file without deciding it. `summary.policy_entries` reports such files per entry as `preempted`, and `--files` shows which entry decided each one. Reopen when reviewers need the per-file view to untangle entry order. On 0.11.1 a12-rulekit asked for a cheaper form, a few example paths under `preempted` and `displaced` ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)); reopen with a second request for either.
- Accepting reference category names without a declaration in `[categories]`, with reports recording their reference meaning. It would change validation and the effective-policy snapshot, as the [category reference](proposals/archive/category-reference.md#excluded) explains. Reopen when the vocabulary of `--guide categories` has held unchanged for a release and a contract defines which meaning wins when a project declares a reference name differently. Since 2026-10-25 the error for an undeclared reference name states what the reference uses it for, which bpmn-lean-experiment confirmed on 0.11.1 while asking again for accepted names.
- Hints in reports when a policy uses a name the category reference replaces, such as `benchmark` for `performance`. Reopen when the vocabulary has held unchanged for a release. On 2026-10-25, agents asked to update two workspaces' policies to make the best use of Locmetry 0.11.1 kept five replaced names from the originals (`benchmark`, `archived-evidence`, `research`, `doc-snippet`, `fixture`), since nothing named the replacement; the vocabulary is unchanged since 0.11.0.
- A display name for a language correction, so a DSL whose comment syntax matches a counter language is counted with that parser but reported under its own name. Reopen when a second project needs one. On 2026-10-25 the public a12-kernel workspace, measured at the commits of its 2025.06-ext5 release, left 47 ANTLR grammars unrecognized, which a C-family counter could count by their `//` and `/* */` comments only under that counter's name; its 529 StringTemplate files match no counter's comment syntax.
- A `reason` on language mappings, which entries and corrections already carry, so a mapping's evidence reaches reports and `explain`. Asked for on 2026-10-25 by an agent that mapped snapshot and fixture formats. Reopen with a second request.
- Reference rows for `conformance`, which a12-rulekit and the private Lean project both declared for spec or corpus suites on 0.11.1, and `guard`, which a12-rulekit declared for repository drift checks ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)). A reference name needs the research checks before it is added; `conformance` has the two projects to start them.
- A count of unclaimed documentation and data in the verbose notes, and an exit status that fails on unclaimed or unused policy, asked for by the private Lean project on 0.11.1, which wrote its own guard ([0.11.1 feedback round](research/agents/feedback-2026-10-25-b.md)). `review` stays source-only, since documentation reaches the fallback as a matter of course, and `jq -e` over the JSON findings already gates. Reopen with a second request.
- A typed purpose in the policy audit's displacements, which today key and merge by the `purpose:category` string and parse the purpose back for notes. Custom serialization would keep the report's string unchanged. Reopen when a category may contain `:` or another consumer needs the purpose, weighing the conversion code against the parse.
- Keeping the category a refinement replaced as runtime-only evidence on file records, which `contract::File` would not serialize, so the audit stops reclassifying each refined file. Reopen when timings show the audit's extra classification matters; the 2026-10-24 cleanup did not demonstrate that it warrants optimization.

## Measurement and Comparison

Candidates from the 2026-10-16 measurement review; the [retired follow-up record](plans/archive/measurement-follow-ups.md#conditional-follow-ups-and-preserved-rationales) keeps their prior-art references.

- Minified-code evidence: report suspicion with the exact property or threshold that triggered it, keeping totals and selection unchanged; generated-code markers shipped on 2026-10-23 ([generated-code markers](proposals/archive/generated-code-markers.md)). Reopen with a real scope problem, after agreeing on sample inputs, false-positive checks and scan cost.
- Duplicate-content evidence: exact-content groups that keep physical totals, since equal bytes can serve different purposes or members; no fuzzy clone detection or unique-content metric without its own contract. Reopen when a consumer needs to locate copied content.
- Binary and encoding policy: establish current-source fixtures before changing defaults, since a NUL heuristic can reject text encodings. Reopen by reproducing the weaker existing-binary observation.
- Git history analytics such as hotspots, coupling and authorship, which bring history-window and identity semantics beyond saved measurements. Reopen with a concrete history workflow existing tools cannot serve.
- Complexity, unique-line and cost metrics, which need independent definitions and validation and do not establish effort or quality. Reopen with a named decision that needs one and an agreed validation corpus.
- An MCP interface, which would have to share policy and result semantics with the CLI. Reopen when a client cannot use the CLI, JSON and schemas adequately.
- HTML, CSV, SQL and OpenMetrics output. Reopen with a named consumer whose needs existing output cannot meet.
- Streaming and resource limits, which change ordering and detail and must never truncate scope silently. Reopen with a reproducible memory, latency or oversized-file problem on a representative corpus.
- Comments after non-ASCII whitespace, such as an INI `;` after a no-break space or a Rust `//` after U+200E, count as code: the fork skips only ASCII blanks before a comment, and its blank symbols cannot all be skipped there, as C's `\` is no blank before `//`. No judged corpus holds one ([step 6 record](research/tokei-fork-step-6.md#ini)). Reopen when a measured file does.
- Archive or remote input, custom lexers and more platforms. Reopen with a representative use case and a feasible test and release matrix.
